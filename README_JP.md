# ゴミ分別ロボット - プロジェクトガイド

ようこそ。このロボットの役割は、タグ付きのゴミを探して接近し、
アームで拾い上げ、種類を識別して、正しいゴミ箱に入れることです。

視覚系（タグ検出・種類分類）はすでに完成しており、そのまま使える
状態で渡されます。基本的に変更は不要です。それ以外の部分（先週の
コンペティションコード）は**参考実装**として渡すものであり、その
まま丸ごとコピーするものではありません。自分たちのリポジトリで、
自分たちのパッケージを一から作ってもらいます。ゲイン調整やポーズ
の追加、分別ロジックの拡張を行うことになるので、「動くけど理解し
ていないコード」よりも「なぜそのコードが動くのか」を理解している
ことの方がずっと重要です。

## 1. ROS2パッケージの作成

まずワークスペースとパッケージを一から作成します。

```bash
mkdir -p ~/trash_sorter_ws/src
cd ~/trash_sorter_ws/src

ros2 pkg create --build-type ament_python trash_sorter \
  --dependencies rclpy std_msgs geometry_msgs sensor_msgs cv_bridge
```

これにより以下が生成されます。

```
trash_sorter/
├── trash_sorter/          <- ここに自分たちのPythonファイルを置く
│   └── __init__.py
├── resource/
│   └── trash_sorter
├── package.xml
├── setup.py
└── setup.cfg
```

作成する各ノードは内側の `trash_sorter/` フォルダに入れます（同じ
名前のフォルダが2つあるため紛らわしい点に注意してください。外側は
パッケージ全体、内側が実際のPythonモジュールです）。

### ノードの登録

`ros2 run` から見つけられるように、各ノードは `setup.py` に登録が
必要です。`setup.py` を開き、`entry_points` に各ノードを追加してく
ださい。

```python
entry_points={
    'console_scripts': [
        'challenge_node = trash_sorter.challenge_node:main',
        'tag_detector_node = trash_sorter.tag_detector_node:main',
        'crane_driver_node = trash_sorter.crane_driver_node:main',
        'gui = trash_sorter.gui:main',
    ],
},
```

`main()` を持つ新しいノードファイルを追加するたびに、ここにも対応
する行を追加してください。この手順を忘れると、ファイルが存在して
いても `ros2 run` からノードを見つけられません。

### ビルド

ワークスペースのルートから実行します（`src/` の中ではありません）。

```bash
cd ~/trash_sorter_ws
colcon build
source install/setup.bash
```

新しいターミナルを開くたびに `source install/setup.bash` を再実行
する必要があります（面倒であれば `~/.bashrc` に追加しておくと便利
です）。

## 2. パッケージ構成 - どこに何を置くか

| ファイル | 役割 | 状態 |
|------|---------|--------|
| `tag_detector_node.py` | 視覚ノード - タグを検出し `/tag_pose` と `/tag_id` を配信する | **完成済み。** 旧リポジトリからそのままコピーしてください。 |
| `crane_driver_node.py` | 低レベルドライバ - シリアル経由でDynamixelサーボと直接通信する | **ハードウェア固有・提供済み。** ハードウェアが同じであればそのまま流用してください。 |
| `arm.py` | アームの高レベルインターフェース（`pick_can()`、`place_left()` など）- 生の関節コマンドを名前付きの動作にまとめたもの | **参考実装。** 自分たちの分別カテゴリ・ゴミ箱に合わせて新しい動作を追加していくことになります。 |
| `base.py` | 走行台車の高レベルインターフェース（`drive()`、`forward()`、`left()` など） | **参考実装。** 基本的にはそのまま動くはずですが、触る前に中身を理解しておいてください。 |
| `robot.py` | `ArmController` と `BaseController` をまとめるだけの薄いラッパー | **参考実装。** 変更が必要になることはほとんどありません。 |
| `poses.py` | `arm.py` の各動作が経由する、あらかじめ定義された関節角度（度数）のポーズ | **自分たちで書き直すファイルです。** 先週のポーズは2カテゴリ・2ゴミ箱用に調整されたものです。今回は3種類（＋発展課題で1種類）あるので、新しいゴミ箱の配置に合わせたポーズが必要です。セクション6を参照してください。 |
| `challenge_node.py` | メインの状態遷移マシン - SEARCHING → APPROACHING → PICKING → SORTING → FINISHED | **TODO付きの骨組みを別途配布します** - このREADMEではなく、タスク一覧を参照してください。 |
| `gui.py` | 関節スライダーと台車移動ボタンを備えたPyQt5コントロールパネル | **デバッグ専用ツール** - 本番の競技ロジックには含まれません。アームを手動で動かして `poses.py` 用の新しいポーズ値を探したり、台車の動きを単体でテストしたりするのに使ってください。競技用のロジックはこのファイル自体には含まれていません。 |

## 3. システムの起動方法

起動順序が重要です。カメラとドライバは、それらに依存する他のノー
ドより先に立ち上げておく必要があります。

**ターミナル1 - カメラ:**
```bash
ros2 run v4l2_camera v4l2_camera_node --ros-args \
  -p video_device:=/dev/video2 \
  -p pixel_format:=YUYV \
  -p image_size:="[320,240]"
```

**ターミナル2 - アームドライバ:**
```bash
ros2 run trash_sorter crane_driver_node
```

**ターミナル3 - タグ検出:**
```bash
ros2 run trash_sorter tag_detector_node
```

**ターミナル4 - 競技ロジックかデバッグGUIのどちらか一方（同時には実行しない）:**
```bash
ros2 run trash_sorter challenge_node
```
```bash
# または、手動でポーズを調整する場合:
ros2 run trash_sorter gui
```
`challenge_node` と `gui` を同時に実行しないでください。どちらも
`Robot`（アーム＋台車）を生成するため、同時に動かすと同じトピック
に対して競合するコマンドを配信してしまいます。

## 4. カテゴリ対応表（視覚システムより）

| タグID | カテゴリ | 日本語 |
|--------|----------|----------|
| 0 | 可燃ごみ | 可燃ごみ (kanenengomi) |
| 1 | ペットボトル | ペットボトル (petbotoru) |
| 2 | 缶 | 缶 (kan) |
| 3 | 不燃ごみ *（発展課題）* | 不燃ごみ (funenengomi) |

`/tag_id` はこれを生のint値として配信します。各IDをアームの動作と
ゴミ箱に対応付けるのは、`challenge_node` のSORTING状態の役割です。

## 5. タグの生成と印刷

```bash
python3 generate_tags.py
```

`tags_output/` にカテゴリごとのPNGファイルが1枚ずつ生成されます。
印刷する際は必ず**「実寸大」「100%スケール」**で印刷してください
- 「用紙に合わせる」は絶対に使わないでください。印刷後は黒い正方
形部分を定規で測り、正確に50mmになっているか確認してください。ず
れている場合は正しい倍率で再印刷するか、`tag_detector_node.py` の
`MARKER_SIZE` を実際に印刷したサイズに合わせて更新してください。
ここがずれていると、すべての距離推定値が同じ比率でずれてしまいま
す。

## 6. 新しいアームポーズの探し方

今回は先週よりカテゴリ数が多いため、新しい配置ポーズ（形状が違う
場合はピック動作も）が必要になります。`gui.py` を使って探してくだ
さい。

1. ドライバノードを起動し、アームに電源が入った状態でGUIを実行し
   ます（`ros2 run trash_sorter gui`）。
2. 関節スライダーを使って、アームを目的の位置（例:新しいゴミ箱の
   上）まで手動で動かします。
3. 各スライダー横の数値ラベルから、結果として得られた関節角度を
   読み取ります。
4. その角度（度数）を `poses.py` の新しいリストとしてコピーしま
   す。既存のスタイル（base, shoulder, elbow, wrist, gripper の順）
   に従ってください。
5. `arm.py` に対応するメソッド（例: `place_center()`）を追加し、
   `place_left()` / `place_right()` と同じパターンで新しいポーズを
   経由するようにします。

## 7. トラブルシューティング

**検出が遅い、または数秒単位で途切れる場合**
実際の配信レートを確認してください。
```bash
ros2 topic hz /tag_pose
```
カメラのフレームレートよりも大幅に低い場合、よくある原因はカメラ
ドライバと検出ノードのサブスクリプション間でのQoSの不一致です
（提供済みの `tag_detector_node.py` では既に対処済みですが、カメ
ラ周りを変更した場合は再確認する価値があります）。

**ノード同士がうまく通信できていないように見える場合**
```bash
rqt_graph
```
現在動作中のすべてのノードと、それらをつなぐトピックをグラフとし
てリアルタイムに描画してくれます。明らかな配線ミス - 本来つながっ
ているはずのノードが接続されていない、トピック名のタイプミス、そ
もそもノードが起動していない、といった問題を見つける最速の方法で
す。「なぜか反応しない」と感じたら、コードを読み込む前にまずこれ
を確認してください。

**カメラ自体が正常に動作しているか、検出とは切り離して確認したい場合**
```bash
ros2 run rqt_image_view rqt_image_view
```
トピックのドロップダウンから `/image_raw` を選択すると、検出ノー
ドを介さずにカメラの生映像を直接確認できます。「これはカメラの問
題なのか、検出ロジックの問題なのか」を切り分けるのに便利です。こ
こで生映像が問題なく映っているのに検出がうまくいかない場合、原因
はカメラではなく `tag_detector_node.py` やパラメータ側にあります。

**距離やオフセットの値がおかしい、または不規則に飛ぶ場合**
1. 印刷したマーカーが正確に50mmかどうか確認してください（セクショ
   ン5参照）。
2. 検出ノード起動時のログ行を確認してください。カメラ行列がどの
   解像度で初期化されたかが出力されるので、実際のカメラの出力解
   像度と一致しているか確認してください。
3. 同じフレーム内に異なる2つのタグが同時に映っている場合、検出ノ
   ードは常に近い方をターゲットにします。検出ノードのデバッグウ
   ィンドウ（または `rqt_image_view`）で、それが実際に起きている
   ことなのか、誤検出なのかを確認してください。

**想定外・間違ったカテゴリIDが出る場合**
検出ノードは、既知のカテゴリ一覧に含まれないIDも含めて、検出した
生のIDをすべてログに出力します（2秒に1回に制限）。このログを見る
ことで、QRコードや光の反射、背景にある無関係な模様など、意図しな
いものを拾ってしまっていないか確認できます。`/tag_id` に配信され
るのはID 0〜3のみで、それ以外はログに出力されるだけで無視されます。
